# 质量验收：判断成立，使用者拿得走

按已确认范围评分；未选模块记 N/A 并说明，不因篇幅短而扣分。
每项 0（缺失/错误）、1（有缺口）、2（充分），写证据位置，不能只打分。
自评不是独立测试，也不能证明营销转化；有独立审阅时分别记录。

| 项目 | 满足的可观察行为 |
|---|---|
| 方向与范围 | 先推荐并等待确认，或正确沿用已有明确授权；部分任务没有膨胀成完整报告 |
| 证据可追溯 | 承重事实有出处、日期、口径、核验状态；缺口未冒充事实 |
| 计算与推论 | 公式/单位/比较对象正确；事实到主张之间的机制成立，无跳步因果 |
| 客户与替代 | 说明为谁解决什么问题、相对什么方案；不把共性包装成独有优势 |
| 主张清晰 | 主线与少量支撑可复述，叙事候选是不同方向而非同义改写 |
| 表达质量 | 对所选渠道自然、有记忆点；双层表达兼顾形象和解释，不靠夸张 |
| 反证与边界 | 回答最强异议，必要时承认优势不足、替代更合适；不把风险藏在附录 |
| 偏好与一致性 | exact 原句未擅改；候选保留；各成品共用事实和主张，状态区分已选/建议 |
| 使用性 | 同事能讲清主卖点、证据和限制；输出匹配所选场景，不把内部稿当对外批准稿 |
| 技术交付 | 所选格式可打开；必要 QA 实跑通过、图文可读；跳过和失败不写成通过 |

## 阻断项

关键计算错误、捏造来源、无证据的承重结论、跳过用户要求的确认、
擅改 exact 项或泄漏内部材料，必须先修；任何总分都不能抵消。
成品交付建议适用项达到 85% 且无 0 分；未达标可交明确标为“待完善”的底稿，
不能伪装验收合格。用户选了哪个范围，就按该范围检查，不要求为满分增加模块。

## 研究复核与最终验收

研究后先验事实、计算、机制、客户与替代；方向推翻时给选项并暂停。
最终再验表达、异议、原句保留及跨成品一致性。
保留一页主张清单：C 编号、通过/待改、证据位置、问题与修正。
篇幅、图表数、新数字数、“惊人总结”数不是质量门槛。旧版单一长报告的页数校准
只代表一个案例，不据此推断其他产品、渠道或短材料应当多长。

## 回放到最终成品

维护时用相同原始材料与任务对照新旧版：
1. 准备完整产品研究、局部营销材料、证据不足/明显不同结构产品等场景。
2. 新会话只给技能、任务与原始材料，不给终稿、预期答案或已知缺陷。
3. 首轮检查方向卡和停点；由测试者提供明确选择，再继续到最终选定成品。
4. 独立评审主张有效性、可复述性、保留项与不适用边界；记录模型、版本、
   用户回复、实际输出、错误、适用项评分。脚本测试与内容评审分开报告。
5. 比较同一场景的新旧输出，修正有证据的失败。没有真实同事试用或成交数据，
   就不能宣称同事成功率或营销转化提升了某个百分比。

原始材料与终稿缺一时写明未完成对应金标准回放。仅有终稿不构成可重复研究的输入包。
私有金标准、真实附件、回放原文只在私有目录；公共 evals 使用虚构/可公开材料，
公开结果只包含已检查无敏感信息的摘要。
