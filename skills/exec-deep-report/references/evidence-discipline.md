## 1. 来源分级

| 级别 | 来源 | 用法 |
|---|---|---|
| L1 | 法律与监管文件（产品资料概要、章程、通函）、公司公告与财报、交易所与指数公司官方文件 | 承重结论必须尽量落在这一级 |
| L2 | 管理人或公司官网的产品页、投资者关系材料 | 可用，注意网页可能未随文件更新 |
| L3 | 权威媒体、数据商、卖方研究的公开摘要 | 可用，注明媒体与日期 |
| L4 | 路演材料、新闻稿、宣传单张；其他 AI 或同事的报告 | 可引用，但要与 L1、L2 或逐项加总交叉核对；后者标“转引” |
| L5 | 社交媒体、论坛 | 只作线索，写入报告须标“待核实” |

## 2. 冲突处理

- 法律文件优先于网页，网页优先于宣传材料。
- 同一张表里的数字使用同一时点；做不到就分列并标日期。
- 两个来源冲突时，两者都写出来并说明，不要默默选一个。
- 材料内部自相矛盾时（例如饼图与逐项加总不一致），单独提示用户，并说明本报告以哪个为准、为什么。

## 3. 标注规范

- 图表下方写“资料来源：机构或文件名，日期；口径说明”。
- 本报告自己算的数，标“本报告测算”，并在注释里写方法和输入。
- 目标、情景、KPI 一律标“建议值，非预测”。
- 无法直接查阅原文、只能从他人报告里取得的数据，标“转引，待复核”。
- 正文标签只用三种：推断、假设、建议。
- 附录固定三部分：数据来源与口径、数据缺口与需要补充的数据、明细表。

## 4. 措辞红线

| 容易写错的 | 正确写法 |
|---|---|
| 已推出、已上市 | 只有查到上市或发行事实才用；只查到注册文件就写“已备案” |
| 文件规定的上限 | 是权限，不是实际值；写“最多可”“上限为” |
| 一致预期、指引 | 是预测，不是已实现；与财报数字分开写 |
| 回测区间的指数表现 | 标明指数发布日，实盘与回测分开 |
| 首只、唯一、独家 | 未经核实不用；改为“据公开检索暂未见同类” |
| 估计的费用或跟踪偏离 | 写清它包含什么、不包含什么，不要把不同口径的数字相加 |

## 5. 内部一致性检查

- 各类占比加总是否为 100%。
- 同一指标在摘要、正文、图表、附录中是否一致。
- 材料宣称的合计与逐项加总是否一致。
- 同一日期的两张图表能否互相推导。
- 任何“前 N 大合计”能否从明细表复算出来。

## 6. 检索纪律

- 不认识的产品、公司、规则名称，先检索再写。
- 涉及现任职位、现行规则、产品现状、费率、规模的内容，一律检索核实。
- 抓取网页时设置内容长度上限，避免一个页面耗尽上下文。
- 只抓取用户给出或检索结果里出现的链接，不自行拼接网址。
- 查不到就写进数据缺口表，不要用常识补。

## 7. 数据缺口表

报告附录固定包含一张表：编号、需要的数据、用途、优先级。用途要具体到“补齐后哪个判断可以从定性升级为定量”。

## 8. 取数单（Excel）列定义

宿主提供 xlsx 技能时可用它生成；否则运行 `scripts/make_datasheet.py`（openpyxl）。一行一个取数需求：

| 列 | 说明 |
|---|---|
| 编号 | 与数据缺口表对应 |
| 指标 | 例如“指数日度收盘” |
| 口径定义 | 币种、是否净总回报、是否复权、统计口径 |
| 标的与代码 | 彭博或 Wind 代码，拿不准写名称并标“代码待确认” |
| 期间与频率 | 起止日期，日、周、月 |
| 首选来源 | Wind、彭博、内部系统、交易所 |
| 备选来源 | 公开渠道 |
| 用途 | 对应的章节、图表与要验证的判断 |
| 优先级 | 高、中、低 |
| 状态 | 待取、已取、无法取得 |
| 回填位置 | 报告中的表号或图号 |

另建一个“复核清单”工作表，列出报告中所有标“转引，待复核”的数字及其出处，方便用户逐项核对。
