# 三种报告骨架

先判断类型，再读对应一节。骨架是默认值，用户的任务说明优先；章节标题最终都要改写成结论句。

## 目录
- A　产品分析与营销方案
- B　机构或行业深度分析
- C　新品机会与候选池研究
- 三类通用的首尾

## A　产品分析与营销方案

**适用**：公司新上或重点产品，要同时回答“产品到底是什么、亮点在哪、怎么卖”。
**典型读者**：管理层加销售团队。销售团队在场时，要给可直接使用的工具。
**核心问题模板**：在什么样的市场时点，这只产品如何做得大、留得住、不伤害信任？

| 章 | 内容 | 必备图表 |
|---|---|---|
| 执行摘要 | 核心问题、三个判断、一句话定位与打法总纲、目标表、近期六件事 | 三情景目标表 |
| 1 起点 | 上市或发布时点的市场坐标；产品在公司战略与产品族里的位置 | 时点事件表、产品族定位表 |
| 2 产品穿透 | 基本要素、规则、集中度、地区与环节穿透、全成本、交易安排；材料口径矛盾单独提示 | 权重加累计图、穿透条形图、成本读法表、敏感度图 |
| 3 投资逻辑 | 把材料里的产业素材组织成一条逻辑链；预测与已实现分开；章末汇总可引用的事实 | 两三张产业图、“已兑现”对照表 |
| 4 标尺与标杆 | 正面、自家、直接同业、反面标杆；对主要竞品的攻防表；客户可能已持有的替代品 | 同业对比表、攻防表 |
| 5 亮点与质疑 | 五个左右亮点，每个带证据与边界；十个以上质疑的标准答法 | 问答表 |
| 6 定位与叙事 | 一句话定位候选与取舍；三层叙事；分客群话术；适配边界；一分钟话术；与自家相近产品的区隔 | 信息屋表、客群表、适配矩阵 |
| 7 营销与分发 | 渠道打法；内容资产；透明度或投资者保护底座；慎用词表；首 13 周日历 | 日历表、慎用词表 |
| 8 产品家族路线图 | 衍生形态、区域分销、指数或方法评审议题、费率路线 | 路线图表 |
| 9 目标与 KPI | 参照系、三情景、KPI 仪表盘 | KPI 表 |
| 10 行动与风险 | 90 天清单、风险矩阵、后续观察清单、结语 | 清单表、风险矩阵 |

**常见坑**：把“多少只成分股”当作分散度；用小权重故事代替大权重事实；只写亮点不写质疑；忽视与自家相近产品的相互蚕食。

## B　机构或行业深度分析

**适用**：对一家机构（交易所、同业、合作方）或一个行业做全景判断，读者往往本身就是该领域的内行。
**典型读者**：老板本人或董事会层级。要求观点锋利、独立客观，不因读者身份而回避批评。
**核心问题模板**：这家机构的增长引擎和结构性短板分别是什么，未来三到五年的关键变量是什么，对我们意味着什么？

| 章 | 内容 | 必备图表 |
|---|---|---|
| 执行摘要 | 核心问题、三到五个判断、最重要的三个数字、对读者的含义一句话 | 关键指标一览表 |
| 1 业务与收入拆解 | 业务线、收入与利润结构、驱动因素、与同业的对标 | 收入结构图、对标表 |
| 2 做得好的 | 每条一个结论句加证据 | 趋势图 |
| 3 做得不好的与结构性不足 | 同上，写清是周期问题还是结构问题 | 对比图 |
| 4 危机与外部威胁 | 竞争、监管、技术、地缘 | 风险图或矩阵 |
| 5 机会 | 按可行性与影响排序 | 机会矩阵 |
| 6 专题 | 用户指定的专题（例如互联互通、某项制度），可展开为多章 | 专题数据图 |
| 7 可以怎么做 | 解决思路或决策选项，分组给出，每项写前提、收益、代价、先行指标 | 选项表 |
| 8 对本公司的含义 | 可做成可拆分的独立附件，便于报告单独对外流转 | 含义与行动表 |
| 附录 | 来源、缺口、明细、无法取得的原始文件清单 | — |

**常见坑**：罗列事实而没有判断；回避对读者所在机构的批评；把专题写成资料汇编；拿不到原文的文件硬写，应当留空并列入缺口。

## C　新品机会与候选池研究

**适用**：为管理层和产品委员会提出值得研究或发行的新产品方向。
**典型读者**：首席执行官与产品委员会。目标是让读者觉得对产品发行有实际业务价值、有启发，并体现对市场的研究深度。
**核心问题模板**：在我们的能力与约束之下，哪些产品值得现在做、哪些值得准备、哪些应当暂缓，依据是什么？

| 章 | 内容 | 必备图表 |
|---|---|---|
| 执行摘要 | 三到五个最优先的方向、各自的一句话理由与最大风险、需要决策的事项 | 优先级总表 |
| 1 市场在发生什么 | 各目标市场的结构变化、资金流向、监管变化 | 市场规模与流量图 |
| 2 同业成败与爆款机制 | 成功与失败案例，抽象出可检验的机制 | 案例对照表 |
| 3 自身能力与约束 | 牌照、渠道、做市、品牌、成本、过往记录 | 能力约束表 |
| 4 候选池 | **完整保留全部候选**，每个写清逻辑、需求证据、可行性、竞争、风险 | 候选池总表 |
| 5 评分与优先级 | 评分维度、权重、结果；暂缓项写明暂缓理由 | 评分矩阵 |
| 6 逐项建议 | 每个候选给正反两面的建议；争议项给分步评估路径，不一步否决 | 分步评估表 |
| 7 验证与取数计划 | 需要补的数据、由谁取、补齐后验证什么 | 取数单 |
| 附录 | 来源、计算文件说明、明细 | — |

**常见坑**：替用户做了取舍（删掉低优先级候选）；只给“做”或“不做”的二元结论；对内部事实（在研清单、初始资金来源）靠猜；数据未到就停工——应当先用公开口径推进，缺口后补。

## 三类通用的首尾

- 封面：标题、副题、读者、日期、版本、保密级别、一段口径声明。
- 目录：手工目录，不带页码（原因见 `docx-pitfalls.md`）。
- 附录固定三部分：数据来源与口径、数据缺口与需要补充的数据、明细表。
- 结尾固定一个“重要提示”提示框：用途、口径、合规审阅要求。
