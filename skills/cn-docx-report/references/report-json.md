# report.json 结构

一个 JSON 文件描述整份报告；`scripts/build.js report.json out.docx` 渲染。样例：`examples/polaris-mini.json`。

```json
{
  "doc": {
    "title": "文档标题（写入文件属性）",
    "headerLeft": "页眉左", "headerRight": "页眉右",
    "cover": { "org": "机构与报告类型", "badge": "版本或密级角标", "title": "主标题", "subtitle": "副标题",
               "product": "产品或对象一行", "tagline": "一句话", "audience": "供谁阅读", "dateLine": "日期",
               "disclaimer": "口径声明（必填，structure_qa F1）" }
  },
  "toc": [["执行摘要", 0], ["第一章　结论式标题", 0], ["1.1 小节", 1]],
  "content": [ ...内容项... ]
}
```

## 内容项

| 写法 | 含义 | 规则 |
|---|---|---|
| `["h1", "第一章　结论式标题"]` | 一级标题（另起页） | 全句结论，不少于 8 字（W1） |
| `["h2", "..."]`、`["h3", "..."]` | 二、三级标题 | |
| `["p", "正文，支持 **粗体**"]` | 段落 | 不留 `**` 未闭合 |
| `["b", ["要点", "要点"]]` | 项目符号 | 每条一行 |
| `["n", ["第一项", "第二项"]]` | 编号列表 | |
| `["t", {"head": [...], "rows": [[...]], "w": [列宽百分比...], "opt": {"boldFirstCol": true, "center": [2], "size": 9, "keep": true, "compact": true}}]` | 表格 | 含外部数据的表其后两项内必须有 `s` 来源行（F3）；`w` 合计 100 |
| `["c", {"title": "标题", "body": ["段落", ["要点", "要点"]], "opt": {"kind": "warn" 或 "note"}}]` | 提示框 | 默认蓝色结论框；`warn` 红色警示（口径矛盾用它）；`note` 灰色说明；报告末尾必须有标题含“重要提示”的提示框（F9） |
| `["f", {"file": "fig.png", "cap": "图 1　图题（日期）", "src": "资料来源：…，日期", "width": 560}]` | 图片 | `file` 相对 JSON 所在目录；`src` 必填（F2）；先用 `chart_style.py` 生成 |
| `["s", "资料来源：…，日期"]` | 来源行 | 放在表或图之后 |
| `["pb"]` | 分页 | 一般不需要，h1 自动另起页 |

## structure_qa 会查什么

F1 封面声明与目录；F2 图有来源；F3 含外部数据的表有来源行（自编工具表降为 WARN）；F4 每章至少一表或图；F5 质疑问答表不少于 10 行（表头含“怎么问”或“质疑”和“答”）；F6 适配矩阵至少两行非适配（表头含“适配判断”）；F7 攻防表“需要先承认的”无空格；F8 情景目标表附近有“建议值”；F9 “重要提示”提示框；F10 无占位符、样例标记词、过程性字眼；W1 标题过短；W2 执行摘要页数（传 `--pdf` 实测）。

## 从其他产出转成 JSON

- 问答表、攻防表、适配矩阵：`t` 项，表头与模板一致，脚本才能识别。
- 口号一页纸：定位句用 `p`，推荐条用 `t`，候选池用 `t`（`opt.size: 8`）。
- 核查备忘：矛盾用 `c` + `kind: warn`；事实清单与复算用 `t`。
